01 — Overview

What Is the Mind's Eye?

The Mind's Eye is a first-person 3D environment. It opens on the smallest possible manifold: a 64-cell seed — one 64-bit SHD-CCP word unfolded into a 4×4×4 cube where every one of the 64 vertices is a packet (energy-frugal by design; you grow larger only when you need to). Fly through it, click any vertex, and program it into a real SHD-CCP packet: a 64-bit word carrying a form, a color quaternion, amplitude, frequency, spin, and a parity bit. You can also switch to larger blank lattices (Box, Toroid, knots) of many thousands of null vertices when a build calls for it. Link programmed packets into chains that thread through 3D space, and when you're done, crystallize the whole construction into one compact, tamper-evident seed that regrows it exactly.

The packet format isn't a toy — it's the same 64-bit SHD-CCP word the rest of the Biomesh uses (defined in scripts/biomesh.js and BioChain_Enterprise/shdccp_kernel.py). So a lattice you build here is made of the same atoms as a biochain, and any data — text, bytes, an existing SHD-CCP stream — can be crystallized into packets and studied in the same space. That shared format is the point: it's a standard that decentralized nodes can all speak.

02 — Navigate

Navigating the Space

There are two camera modes. Orbit is the default: drag to rotate, scroll to zoom, always looking at your last selection. Click the canvas to enter FPS mode (pointer-lock) and fly:

WASD — move
Z / C — ascend / descend
Space — play/pause flow
G — toggle chain mode
Shift+click — multi-select
Esc — back to orbit

The Lattice panel (top-right) picks the shape — Box, Toroid, Cylinder, Lissajous Knot, or Trefoil Knot — its dimensions, the approximate packet count, and an RNG seed (used only by the two knot shapes, so their vertex layout is reproducible). Generate lattice rebuilds the scaffold. Flow (Space) animates the whole lattice — packets and chains move with it.

03 — Packet

The 64-bit SHD-CCP Packet

Every programmed vertex is exactly one 64-bit word. The bit layout is the canonical Biomesh SHD-CCP format — identical to crystallize() / packWord() in scripts/biomesh.js:

amp3Amplitude 0–7 → scales the shape by φ^amp (golden-ratio powers).

Why it matters

Because the word is the canonical format, a chain of programmed vertices is literally a stream of SHD-CCP words — the same wire format a biochain body uses. That's what lets a lattice you build here be published, traded, and regrown anywhere in the mesh.

04 — Chains

Chaining Packets

A chain is an ordered path through packets — the structure that turns a scatter of vertices into a lattice system. Chains render as glowing polylines and stay glued to their packets while the lattice flows.

1

Enter chain mode

Press G or toggle Chain mode in the Chain panel. A badge appears top-left.

2

Click vertices in order

Each click appends that vertex to the current chain. A null node clicked in chain mode is auto-programmed with the editor's current form, so a chain is always made of real packets.

3

Finish or start a new chain

Enter or Finish chain commits the current chain; Start new chain commits it and begins another. Undo last link and Clear all chains are there too.

Chains are part of the seed

Chains are stored in the seed as ordered lists of vertex indices, so regrowing a seed rebuilds every chain exactly as you drew it.

05 — Raw data

Raw Data → SHD-CCP Packets

The Mind's Eye can ingest any data and crystallize it into packets you can then study in the space. Open the Raw data → packets panel, paste your data, choose how to interpret it, and place it:

ControlWhat it does
DataThe raw input — a sentence, a hex dump, anything.
Interpret asText (UTF-8) encodes the string to bytes; Hex bytes parses space/comma-separated hex.
Start indexThe vertex to begin laying packets from (defaults to your last click).
Auto-chainAutomatically links the laid packets into one chain.
Crystallize & placeChunks the bytes into 8-byte groups, runs each through crystallize() (a real form-9 word with valid parity), and programs consecutive vertices with them.
 
// each 8-byte chunk becomes one canonical crystal word
bytes  = UTF-8("decentralized shd-ccp standard")   // 30 bytes
chunks = 8-byte groups                              // → 4 chunks
word   = crystallize(chunk)                       // form 9, payload = length, parity set
place  at index, index+1, …  + auto-chain

This is how "any input becomes a standard"

The crystal words are byte-identical to what the Python kernel and every other Biomesh surface would produce for the same bytes. So data crystallized in the Mind's Eye is portable to any node — the packets, and the seed that captures them, are the shared representation.

06 — Seed

The Seed

A seed is the compact, self-describing recipe for the entire lattice system you built — the scaffold shape, every programmed packet, and every chain — plus a hash that fingerprints it. It does not store the tens of thousands of empty null nodes; it stores what you created, referenced by index, so it stays tiny and regrows deterministically.

Seed Anatomy

{
  "v": 1,
  "shape": "Box",                // scaffold shape…
  "params": { "boxSize": {"x":100,"y":100,"z":100} },
  "count": 40000,                // …+ params + count + rngSeed fully
  "rngSeed": 1337,               // determine every vertex position
  "nodes": [                     // programmed packets, by index
    { "i": 10, "w": "12FF7828FF000030" },
    { "i": 100, "w": "90663A6FB100081C" }  // ← a data crystal (form 9)
  ],
  "chains": [ [10, 20, 30], [100, 101, 102, 103] ],
  "hash": "0xaf5f0a3e"          // fold32 over the canonical form
}

Because Box / Toroid / Cylinder generation is deterministic, and the two knot shapes use the stored rngSeed, regenerating the scaffold from shape + params + count + rngSeed reproduces the exact same vertex at every index. That's why storing packets by index (not by position) is enough to regrow them precisely.

Regrow & Verify

Build / Regrow

Build serializes the current scene into the seed box. Regrow parses a seed (built, pasted, or loaded from a file), regenerates the deterministic scaffold, and re-programs every packet and chain — the whole system reappears, and the recomputed hash is checked against the stored one.

Verify

Verify recomputes the seed hash and checks every packet's parity bit without touching the scene. A single flipped character anywhere in the seed changes the hash — so tampering is caught immediately.

Copy · Download · Load file

A seed is just text. Copy it, download it as a .latticeseed.json, or load one from disk. That file is the portable artifact — hand it to anyone running the Mind's Eye and they regrow your exact lattice offline.

07 — Standard

The Shared Standard

The whole design points at one goal: decentralized nodes working from a shared Mind's Eye standard. Three layers make that real:

1

The packet is canonical

Every word is the exact 64-bit SHD-CCP format shared by biomesh.js and shdccp_kernel.py. Two independent nodes crystallize the same bytes into the same word.

2

The seed is portable

A seed is plain, hash-stamped JSON. Downloaded or copied, it regrows an identical lattice on any node — no server required.

3

Publish onto the mesh

Publish grows the seed string into a biochain via biomesh.js and certifies it with your seal, so it becomes tradable and traceable like any other biochain. Another node fetches that biochain, recreates the seed text, and regrows the lattice.

Offline-first, mesh-optional

The build / chain / raw-data / seed / regrow core runs entirely in your browser with no backend. Publishing is the optional bridge onto the shared mesh — and if it's unavailable, the Download/Copy seed is still the full standard, ready for any node to import.

08 — Pump

The Synchronization Pump

A static lattice is a snapshot. The synchronization pump makes it breathe — a torsional, Markov, one-way "zero-point pump" (ported from Department V's Loom_Weave) that drives the whole substrate through a 720-frame cycle (or any length you set) so that every SHD-CCP packet interacts with every other. Out of those interactions a scalar field grows, which you can bake back into the packets themselves.

🫁

Breath

The substrate inhales and exhales from the zero-point center once per cycle, unfolding a 4×4×4 tessellation.

🌀

Torsional pump

A one-way Markov charge pulse travels inside→out through radial shells; inner shells spin faster — a torsional twist.

📈

Scalar field

Pairwise packet couplings (the matrix field) accumulate; implied-quadrance backprop returns them inward as a scalar field.

How the Breath Works

Each frame has a cycle-time t = frame / frames. Five things happen, in order:

1

Breath

breath = 1 + sin(π·t)·amp pushes every packet radially out from the zero-point center and back — one inhale/exhale per cycle. The tessellation shell scales with it.

2

Torsional one-way Markov pump

Charge is injected at the innermost packet and flows strictly outward, shell by shell — irreversible, Markov. Inner shells also rotate faster, twisting the substrate.

3

Interaction (the matrix field)

Any two packets whose breathing positions fall within reach couple: coupling = charge × affinity / (1 + Q), where Q is the quadrance (squared distance) and affinity is 1 − hamming(word_a, word_b)/64 — near, charged, and alike packets interact most. Each coupling adds to both packets' scalar.

4

Implied-quadrance backprop

The phase-conjugate return: each shell's scalar flows back inward, quadrance-weighted (/(1+Q)), so the field concentrates toward the zero point — matrix field → scalar field.

5

Render

Packets recolor by their scalar value, interaction links draw between coupled pairs, and chains follow the breathing packets.

Deterministic → auditable

The whole cycle is a pure function of the packets and the pump parameters, so the same setup always yields the same interaction count and scalar field. At cycle end the pump prints a cycleHash (a fold32 fingerprint of the scalar field + parameters) — the breath is replayable and verifiable, exactly like a seed.

09 — Environments

Codex Environments

A blank 40,000‑vertex box wastes energy. An environment is a small, pre‑built starter area — a boundary manifold you design once and load as the default substrate, so biochains have somewhere meaningful to grow and link. It bundles four things into one loadable object: a boundary, a codex prior, pump parameters, and a growth frontier. Think of it as building the rooms of a house so that when new data streams attach, the system already knows roughly where they belong.

The 64-Cell Seed (the default manifold)

The Mind's Eye opens on a 64-cell seed: one 64-bit SHD-CCP word unfolded into a 4×4×4 cube. Vertex index i = z·16 + y·4 + x maps to bit i of the seed word — a set bit makes that vertex an active Platonic solid, a clear bit a dim 0D point, and either way it is a full, parity-valid SHD-CCP packet. So a single 64-bit seed is the whole starting manifold: the tiniest, most energy-frugal substrate there is, and the first tessellation you actually see.

From there it grows fractally. Fractal step + raises the level: level L is a 4ᴸ-per-axis grid where a vertex is active only where the seed's pattern is set at every 4× scale (a self-similar, Cantor-style intersection). If 33 of the 64 seed bits are set, level 2 has 33² = 1089 active cells inside a 16×16×16 grid — the same pattern nested inside itself, with the rest left as free room for chains and folds. The 4×4×4 base gives four fractal steps to unfold from one seed before you build into larger systems. Change the seed word (or 🎲 vary it) and the entire manifold — at every level — re-derives deterministically.

Why start at 64 bits

Nobody's Mind's Eye should be a giant blank box burning energy. One seed word → 64 packets is enough to see the first tessellation and to carry a complete, shareable idea; you only tessellate up (or switch to a larger blank lattice) when a build genuinely needs the room. A full 64-cell has no spare vertices, so an in-place SPLIT reports "saturated — tessellate up" rather than silently doing nothing.

The FORM Split & Gates

The 4‑bit FORM field is split by its top bit: clear → a geometry, set → a gate. That gives eight of each without a new field.

Geometry (0‑7)
00D Point
1‑5Tetra · Cube · Octa · Dodeca · Icosa (Platonic solids)
64D Hypercube
78D E8 Lattice (also the shape kernel data‑crystals show as)
Gate (8‑15)
8 ⊗ HALTstop the fold program
9 ● SEEDidentity / anchor cell
10 ⟳ ROTrotate by spin (torsional twist)
11 ⊕ XFOLDXOR‑fold with neighbour (annihilation knot)
12 ⇋ MIRRORphase‑conjugate reflect (backprop hand)
13 ⧈ SPLITexpand a cell into the next cubic shell
14 ⧉ MERGEfold the outer shell inward (collapse)
15 ⛓ LINKentangle: bind to the nearest frontier cell

Each seed is a pseudo‑quantum logic gate

The gate set is deliberately a closed, bounded, halting instruction set — ROT/MIRROR/XFOLD are (near‑)reversible, SPLIT↔MERGE are inverses, and there are no jumps — so a fold program always terminates and its energy is bounded, exactly like the codex ABI it extends. A kernel data‑crystal (form 9 from crystallize()) is disambiguated from the SEED gate by a raw‑word flag, so all eight gate slots stay usable.

Fold Programs & Cubic Expansion

Program some vertices as gates and the ordered gate packets become a fold program. Run fold program executes them in index order over the cubic expansion grammar — 1 → 3 → 7 → 6 → 12 → 64 (singularity → axes → pivots → faces → edges → cube‑cell), the inverse of the pump's collapse. SPLIT advances a tier and spawns children on the next shell (bounded by the energy cap); MERGE collapses the outer shell; ROT, XFOLD, MIRROR and LINK transform or entangle the live cells; HALT stops. The run is deterministic and prints a hash — it's a reproducible fold, not a one‑off animation.

  "codex":    "…CODEX/1 packet stream…",   // GEAR·PRIME·HALT prior
  "pump":     { frames, breath, torsion, reach, backprop, expansion },
  "frontier": [ 700, 720, 740 ],          // where new biochains may attach
  "hash": "0x281031b9"

The Boundary designer folder is where you author one: pick an energy‑frugal boundary size (8k / 20k / 40k), program the starter area, toggle Frontier mode to click the growth edge (gold rings), Attach codex prior, then Build/Export the environment. Loading it (or Regrow on an environment) rebuilds the boundary, restores the frontier and pump parameters, and re‑binds the codex — verified deterministic (wrecking the scene and reloading reproduces the same hash).

FLUX & CRYST

Simulation is metered in FLUX — the free, infinite meter: breathe, fold, and iterate codex+biochain combinations in the lower toroidal layer as long as you like; the only cost is time. When you find a combination worth committing, CRYST — the scarce, compute‑backed credit — is spent to crystallize it up the tiers. The Crystallize action is gated to the pump's crystallization windows (start, half, and full cycle — the tri‑gear sync points from pump_clock.py); outside a window it's refused. It estimates a CRYST cost from the committed work and, when signed in, grows the environment into a certified biochain on the mesh.

Free to explore, pay to commit

Everything up to crystallization is FLUX‑free and offline. CRYST is only spent at the moment you push a good codex+biochain environment up for permanent crystallization — the one operation whose backing (compute) is genuinely scarce.
